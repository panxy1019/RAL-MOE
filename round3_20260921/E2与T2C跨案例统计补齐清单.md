# E2 与 T2-C 跨案例统计补齐清单

## 1. 目标与边界

为 Circular cylinder、Centered square 和 Fluidic pinball 建立可并列呈现的外层路由与融合统计，补齐论文实现附录，避免将 Square 配置误认为三个案例的统一设置。

本文件是统计任务清单，不是新完成的实验报告。已有信息来自用户提供的 2026-09-21 E2 核实报告；填表时仍须绑定实际运行记录。缺少证据的项目标为“未核实”，不存在或未实施的实验标为“不适用/未实施”，不能填零或复制 Square 参数。

本轮优先只读整理现有源码、配置、检查点、缓存和评价结果。不要为补齐表格擅自启动重训或补做新的 held-out 实验。

## 2. 必须区分的对象

- **E2 网络训练**：参数输入，chart-assigned 标签监督，输出 S/H/P 偏好。
- **E2 Top-1 评价**：使用训练好的 E2 选择候选；本身不是另一个训练任务。
- **T2-C gate 训练**：冻结 E2 与候选预测，利用初始历史描述量学习融合修正；是否冻结须逐运行确认。
- **候选支持协议**：谁提供候选、哪些参数和窗口进入评价，不等于 E2 自动判断适用性。
- **内部专家组路由**：属于 specialist 内部，不纳入本次 E2 网络参数统计。

## 4. 统计任务 A：每个案例的 E2 数据协议

对每个 train/validation/test split 分别记录：

1. 标签来源：chart 归属、物理流态标注还是候选误差排序。
2. 标签输出顺序及编码，例如 S/H/P 对应 0/1/2。
3. 训练单位：每个 chart 内唯一 Re、完整轨迹还是窗口。
4. 标签样本总行数及 S/H/P 各类行数。
5. 全局唯一 Re 数、唯一物理轨迹数，以及轨迹的定义。
6. 相同 Re 是否对应多个初始条件或多条轨迹。
7. 同一 split 内跨 chart 的重复 Re 数及多标签处理方式。
8. train/val/test 间 Re 交集与轨迹交集，分别统计，不相互替代。
9. Re 覆盖范围，必要时提供完整列表作为附录或机器可读附件。
10. held-out 数据是否参与标准化、标签生成、训练、选择或候选支持构造。

## 5. 统计任务 B：E2 结构、标准化、训练与选择

### B1. 网络和输入

- 层宽、隐藏激活、每层 bias、输出顺序、参数量。
- 是否仅输入 Re，有无历史、时间、chart、额外校准或温度。
- softmax 位于模型还是调用端。
- 标准化 mean/std 的数值、拟合数据单位、population/sample std、常数特征保护规则。
- 标准化参数是否随检查点保存，并在评价端正确复用。

### B2. 训练和检查点选择

- 分类损失形式、类别权重计算单位及附加正则项。
- optimizer、初始 lr、weight decay、scheduler、最低 lr、总步数/epoch。
- batch size、有无放回抽样、随机种子、gradient clipping。
- 训练设备、数值精度；无证据时留空，不推测。
- 验证频率、选择指标完整表达式、tie-break、selected step/epoch。
- 是否使用验证分类指标，是否包含训练批 loss；不要统一写为 validation CE。
- 检查点路径、SHA-256、模型类、训练与正式评价入口。

## 6. 统计任务 C：E2 Top-1 的评价范围

每个实际评价运行记录：

- 全三类 Top-1，还是预先给定候选对内的 Top-1。
- 测试单位为 Re、轨迹、窗口还是时间点；同一 Re 多窗口是否重复计数。
- 每个 Re 的窗口数、初始化规则、预测步数 K、对应物理时长。
- accuracy、balanced accuracy、macro-F1、confusion matrix，注明 split 和聚合单位。
- 如报告 margin，明确是在三类概率还是候选对归一化概率上计算。
- 分类正确率与所选 ROM 的场误差分别记录，不互相替代。
- 是否有完整时间跨流态转变测试；静态参数分类不能支持该主张。
- 是否映射到论文中的具体表格/行/指标。

Circular 已有 Top-1 测试材料应优先整理；它并不证明 Circular 已完成相邻双候选的 T2-C 融合评价。

## 7. 统计任务 D：T2-C 是否存在以及实际配置

先对每个案例填写：未实施、仅 development、已有 held-out 但未映射、正式映射闭环。仅对有证据的运行继续统计。

### D1. 模型与输入

- 候选对及其有序排列，alpha 对应哪个候选。
- gate 输入参数和描述量维数、每个描述量定义。
- 描述量来自多少个初始化状态，有无未来参考状态泄漏。
- gate 的输入 mean/std 拟合单位及数据划分；与 E2 标准化分开记录。
- 网络层宽、激活、bias、参数量、最后一层初始化。
- alpha 是窗口固定、时间变化还是分通道变化；速度与压力是否共用。
- E2 logit、裁剪和数值保护的准确计算顺序。

### D2. 训练和控制实验

- gate 训练时 E2 和 specialist 是否冻结，候选是否来自缓存。
- 损失是相对误差还是平方相对误差；速度/压力权重；分母数值保护。
- 时间、窗口和参数的聚合顺序。
- optimizer、lr、weight decay、scheduler、总步数、batch、采样、裁剪、seed、precision。
- 验证频率、worst-parameter 或 pooled 指标、tie-break、selected step。
- full T2-C、mu-only、固定 alpha、固定偏置等控制分别列出：输入、可训练参数、拟合 split、选模规则和实验状态。
- 多种子仅改变 gate，还是连同 E2/候选重训？不要把 gate variability 写成全流程不确定性。

## 8. 统计任务 E：候选支持、缓存和预检

逐案例、候选对、split 记录：

- 候选集合由命令行/协议、参数区间、验证阈值还是模型产生。
- source chart 与另一候选的共同参数支持规则。
- Re 列表、轨迹 ID、窗口起点、windows/Re、总窗口数、K 和物理时长。
- specialist、E2、gate、缓存与 evaluation JSON 的身份绑定。
- 是否存在有限性、幅值或其他预检；实际阈值、参考范数和使用的真值来源。
- 失败处理：整份终止、逐窗过滤还是其他方式；失败数量、排除数量与最终分母。
- 是否真正实现动态适用性、连续支持外推和弃权；未实现必须明确记录。

Square 已核实为预定 SH/HP 支持和整体 fail-closed 预检。held-out 幅值检查使用 held-out 参考范数，不是可部署的在线 mask。虽然现有四份缓存均无失败、未删样，也不能据此声称具备自动稳定性或 OOD 判定能力。

## 9. 统计任务 F：正式结果映射与结论边界

对每个拟放入论文的结果建立：

论文表格行 → 比较方法 → split/参数/窗口 → 评价 JSON → 评价脚本 → E2/gate/候选检查点 → 缓存。

同时核对：

- reference 是原始 CFD 场，还是 POD 重构参考场。
- 指标是终端步还是全窗口；先时间后轨迹还是先 pooled。
- 误差单位是比例还是百分数。
- 比较是否共享相同候选、窗口和真值。
- 是否包含误差排名 oracle，不能将其当作可部署方法。
- Pinball 现有 development validation comparison 是否被误用为 held-out 结果。

找不到 Pinball 正式 held-out 映射时，完成本轮统计的正确输出是“仅确认 development”，不是推测最终结果来源。

## 12. 执行优先级与完成标准

1. 优先统一 E2 的样本单位、标签、split 和正式检查点身份。
2. 补 Circular 已有 Top-1 资料，确认 Pinball development 的真实范围。
3. 汇总有证据的 gate 配置、候选缓存和结果映射。
4. 最后生成三张论文候选表及逐段修改建议。

本轮完成不以“三个案例所有格子均有数字”为标准，而以所有重要格子都有证据支持的值或明确的缺失状态为标准。若真正缺少实验，可另列后续实验需求，等待用户决定后再运行。
