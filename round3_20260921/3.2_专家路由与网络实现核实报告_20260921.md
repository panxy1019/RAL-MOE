## 1. 结论先行

本轮不能支持“Circular、Square、Pinball 的九个 S/H/P 实例都使用同一套 structured sparse-MoE specialist”这一笼统表述。

- **可绑定到具体评价检查点、源码和完整 state shape 的 sparse-MoE 实例有 5 个**：Circular H、Circular P、Square S、Square H、Square P。2026-09-21 已重新计算这 5 个 checkpoint 和对应 live source 的 SHA-256，与既有审计记录一致。
- **Circular S 的论文结果身份仍未闭环**。现有 S4 checkpoint 只能作为诊断模型，不能冒充论文 Circular Steady 结果。
- **Pinball S/H/P 已找到的 B1 候选均为普通 Deep-FNN 型模型，不含组路由、通道 Top-2、共享专家或结构化线性/二次专家分支**。其中 Pinball P 的结果数值和路径均指向 `Deep_FNN_H3`；Pinball H 的现有核查记录明确 `heldout_loaded=false`。因此这三者不能作为第 3.2 节 sparse-MoE 实现细节的实例证据。
- 对确认的 sparse-MoE 类，组路由与通道路由的输入均为 **`[z; standardized xi]`**，不是只用 `xi` 或只用 `z`。组选择为逐样本 hard Top-1；学习式组路由使用 straight-through 路径。通道 Top-2 在已选组内、对 6 个 routed experts 竞争；共享专家不参与竞争并始终随已选组激活。
- 路由权重链为：温度 softmax → Top-k 保留 → 选中 routed mass 重新归一化 → 配置给定的 shared/routed 比例分配。Circular H/P 为 `1.0:0.75`，所以共享权重为 `4/7`，两个 routed experts 合计 `3/7`；Square S 为 `1.0:0.85`，不能沿用 `4/7`；Square P 与 Circular P 相同；Square H 结构与 Circular H 相同，但其最终 overlap evaluator 是 data-only 输出例外。
- 专家非线性分支确实使用 `concat(z,s)`；显式线性分支为 **无偏置** `Linear(s,out,bias=False)`；低秩二次分支为每个输出分量独立的两个 `[out,4,state]` 因子收缩，没有额外 `W_o`。
- 原版 Circular H/P 的两个二次因子被同时置零，因乘积结构导致该分支保持零；原版结果不能证明二次分支有效。修正版只将一个因子置零、保留另一个随机初始化，已确认分支能学习，但性能收益并不稳定。
- 压力并非统一的凸组合。确认的 Circular H/P 与 Square P 使用 `b_next = gamma ⊙ b_PP + rho_p`，即 gate 只缩放 PPE base，学习修正不乘 `(1-gamma)`。Square S 为 baseline base+residual；Square H 的最终 overlap 路径直接输出 learned velocity RHS/pressure，不使用存储的 PPE gate 组装结果。
- RK 阶段固定的是 `b_n`、历史、参数等上下文，**不是固定整个 `xi/z/router`**。每个 trial velocity 都重新计算 Galerkin RHS、当前特征、编码、组选择、通道 Top-2、权重和专家输出。压力在速度 macro-step 后重构，历史随后移位。

因此，第 3.2 节应写成“统一接口 + 明确实例例外”，不能把五个已确认 sparse-MoE 的实现推广到尚未闭环的 Circular S 或 Pinball S/H/P。

## 4. R01：组选择

### 4.1 输入和打分网络

对已确认的 structured sparse-MoE 类，先计算

```text
z = Enc(xi_std)
r = concat(z, xi_std)
l_grp = Linear_h_to_G(Dropout(SiLU(Linear_(D+h)_to_h(LayerNorm(r)))))
```

因此组路由输入维数是 `D+h`。所有 Linear 均含默认 bias；dropout 为 0.04。源码证据：

- `train_periodic_moe.py:1603-1610`：group router；
- `train_periodic_moe.py:1895-1912`：`z`、`[z;x]` 和 group gate 的实际 forward；
- `train_periodic_moe.py:1735-1739`：encoder 后 refinement residual。

### 4.2 logits 到 hard Top-1

设每个样本的组 logits 为 `l^g`，温度为 `T_g`：

```math
p_g = softmax(l^g/T_g),
g^* = argmax_g p_g.
```

训练实现并非纯不可导 argmax，而是

```math
q = onehot(g^*),
\tilde q = q - stopgrad(p) + p,
```

即 forward 为 hard one-hot、backward 沿 softmax 概率传播。实现位于 `train_periodic_moe.py:1389-1410`。选择在 tensor 最后一维上对每个 batch 样本独立执行；后续 `active = group_weight.squeeze(1) > 0` 也是逐样本掩码（`1835-1852`），不是整批或整轨迹共享选择。

没有额外 additive routing noise。dropout 是路由 MLP 的常规 dropout，不能称为 noisy Top-k。gate floor 配置均为 0；若未来配置非零，硬零支持会被 floor 平滑，这一点应与当前实例区分。

训练还存在 group balance、entropy、按 Reynolds-number 分区的 supervision loss（`train_periodic_moe.py:2023-2034`）；这属于训练正则，不改变推理时上述 hard Top-1 定义。

### 4.3 单组和固定组

- Circular H、Square H：`G=1`，组选择退化为唯一组，不应称为“学会的组路由”。
- Square P：checkpoint 架构有三组，但部署配置 `fixed_regime_group=1`，直接构造 group 1 的 one-hot；不由输入 logits 决定。
- Circular P、Square S：三组学习式逐样本 hard Top-1。
- Circular S 与 Pinball：无充分证据支持套用该定义。

并列 logits 没有自定义 tie-break；实际行为由 `torch.topk/argmax` 的底层实现决定。论文无需声称特定稳定并列规则。

## 5. R02/R03：通道 Top-2 与混合权重

### 5.1 通道路由器

速度和压力各有独立参数的 router ModuleList，但共享同一个 `Enc(xi)` 输出。每个已选组 `g*` 有两套独立打分：

```text
l^u = Router^u_g*([z;xi_std]) in R^6
l^p = Router^p_g*([z;xi_std]) in R^6
```

结构均为：`LN(D+h) -> Linear(D+h,h) -> SiLU -> Dropout(0.04) -> Linear(h,6)`。源码：`train_periodic_moe.py:1611-1634`。

Top-2 只在已选组内的 6 个 routed experts 中进行。shared expert 位于单独的 `*_shared_experts` ModuleList，不进入这 6 个 logits，不参加 Top-2，随已选组始终计算。速度/压力“通道”是两个完整输出向量分支，不是每个 POD 输出分量各自路由。

若候选数不大于 `top_k`，代码回退为全部 softmax；五个确认实例均为 `6>2`，未触发该分支。训练与评价的 `top_k=2` 相同，没有评价时另加噪声或 mask。

### 5.2 完整权重链

对通道 `c in {u,p}`、已选组 `g*`，令

```math
p_e^c = softmax(l_e^c/T_c),
K_2^c = Top2(p^c),
\bar p_e^c = I[e\in K_2^c] p_e^c /
              \sum_{j\in K_2^c}p_j^c.
```

配置给出 `lambda_0=shared_scale`、`lambda_r=routed_scale`，则

```math
omega_0^c = lambda_0/(lambda_0+lambda_r),
omega_e^c = lambda_r/(lambda_0+lambda_r) * \bar p_e^c.
```

最终组内输出为

```math
M^c = omega_0^c E^c_shared +
      sum_(e in K_2^c) omega_e^c E^c_e.
```

数值稳定项 `EPS` 加在选中 routed mass 的归一化分母；shared/routed 配置分母用下限 `1e-6`。源码：`train_periodic_moe.py:1395-1409, 1817-1876`。

实例差异：

- Circular H/P、Square H/P：`lambda_0:lambda_r=1:0.75`，所以 `omega_0=4/7`、routed 总质量 `3/7`。
- Square S：`1:0.85`，所以 shared 为 `1/1.85≈0.54054`、routed 总质量 `0.85/1.85≈0.45946`。
- shared 没有自己的 input-dependent score；它的比例是配置常量。
- 速度和压力在同一实例中使用同一 shared/routed 比例，但 router 参数和 Top-2 支持独立。

### 5.3 真实 checkpoint 前向证据

Circular H/P 已完成只读 hook 验证：

| 实例 | 严格加载 missing/unexpected | 记录决策 | Top-2 与 gate 一致 | 最大质量和误差 | hook on/off prediction | checkpoint/model 状态 |
|---|---|---:|---|---:|---|---|
| Circular H | `[] / []` | 6,720 rows | 是 | `6.80e-8` | 全窗口 bitwise equal | 未改变 |

另有 synthetic dispatch 覆盖 H 的 225 个、P 的 675 个组/速度 pair/压力 pair 组合；每个合法支持均保持相同 active-parameter count，prediction 与 diagnostic-stack 输出 bitwise equal。该 synthetic 检查验证执行图和支持，不替代真实数据精度评价。

## 6. N01：`xi`、`z`、`s` 的精确定义

### 6.1 当前特征顺序

当前时刻 base feature 的实际顺序是：

1. 归一化参数 `(Re-center)/scale`；
2. `Re_ref/max(Re,EPS)`；
3. 若 `phase_harmonics=H`，依次加入 `sin(k theta), cos(k theta), k=1..H`；
4. 当前 `a_n`；
5. 当前 `b_n`；
6. 当前 Galerkin RHS `g_n`；
7. 11 个派生量：低/中/高模态范数、`||b||`、`||g||`、`a` 能量、`b` 能量、总能量、低模态能量占比、高模态能量占比、压力/速度范数比。

源码：`train_periodic_moe.py:1047-1096`。

随后对两个历史 lag 分别追加

```text
[a_(n-l), b_(n-l), g_(n-l),
 a_n-a_(n-l), b_n-b_(n-l), g_n-g_(n-l)], l=1,2.
```

源码：`train_periodic_moe.py:1175-1190`。因此不是简单把三个 `[a,b,g,mu]` block 拼接；当前论文的抽象 `Feat(H,mu)` 可以保留，但实现附录必须披露差分和派生量。

设 `H` 为 phase harmonic 数，特征总维数为

```math
D = 13 + 2H + 5(2d_u+d_p).
```

这与五个已确认实例的 `D=493,501,91,178,431` 一致。`dt` 不进入网络特征，只供积分器使用。整个 `xi` 使用各 chart 训练集拟合的 `x_mean/x_scale` 统一逐列标准化；RHS target、pressure target 另有各自 output scaler。

### 6.2 encoder

`z=Enc(xi_std)` 的主干为三层：

```text
Linear(D,h)-LayerNorm-SiLU-Dropout(0.04)
Linear(h,h)-LayerNorm-SiLU-Dropout(0.04)
Linear(h,h)-LayerNorm-SiLU
```

之后有 `num_blocks-1=2` 个 refinement residual blocks：

```text
z <- z + Linear(h,h)(Dropout(SiLU(Linear(h,h)(LayerNorm(z)))))
```

因此配置中的 `num_blocks=3` 不能解释为三个 refinement blocks。

### 6.3 消费者和 state slice

| 张量 | 构造/维数 | 主要消费者 | 备注 |
|---|---|---|---|
| `xi_std` | `B×D` | encoder；与 `z` 拼入所有 routers | 包含当前和历史，已标准化 |
| `z` | `B×h` | group router、u/p channel router、所有专家 nonlinear branch、pressure confidence head | u/p 专家共享 encoder，不共享专家参数 |
| `r=[z;xi_std]` | `B×(h+D)` | group 和 channel routers | 不是专家 nonlinear 的输入 |
| `s^u` | `B×d_u` | u expert 的 linear/quadratic；也与 `z` 拼入 nonlinear | 从 `xi_std` 当前 `a` slice 取得 |
| `s^p` | `B×(d_u+d_p)` | p expert 的 linear/quadratic；也与 `z` 拼入 nonlinear | 当前标准化 `a,b` 拼接 |
| `gamma` | `B×d_p`（adaptive） | PPE base 缩放 | 由 `z` 经独立 confidence head |

`s` 的 slice 代码为 `train_periodic_moe.py:1788-1791`。物理场 POD 编码与这里的学习 feature encoder 是两件事，论文中不应混称。

Square H 最终 data-only evaluator 是重要例外：Galerkin RHS 可仍出现在输入 feature 中，但并不作为 `F_G + residual` 的加性 backbone 使用。Pinball Deep-FNN 候选也不能套用上述 sparse-MoE tensor flow。

## 7. N02/N03：单个专家的等价 forward

### 7.1 非线性分支

对通道状态 `s`，实际 nonlinear branch 为

```text
y0 = GELU(Linear(h+dim(s),h)(LayerNorm(concat(z,s))))
for block in 1..B:
    y <- y + rho_block * Linear(m,h)(Dropout(GELU(Linear(h,m)(LayerNorm(y)))))
N(z,s) = Linear(h,d_c)(LayerNorm(y))
```

每个 residual block 的 `rho_block` 为可学习标量，初始化 0.1。Circular/Square H 的 `B=4,m=1024`；其余已确认实例 `B=3,m=768`。shared 与 routed experts 同构，但不同组、不同通道、shared/routed 之间不共享 expert 参数。

### 7.2 线性和低秩二次分支

实际专家为

```math
[E^c(z,s)]_o = [N^c(z,s)]_o
 + [L^c s]_o
 + kappa \sum_{j=1}^{q_b}
   (U^c_{ojs}s_s)(V^c_{ojs}s_s),
```

其中：

- `L = Linear(state_dim,out_dim,bias=False)`，是 linear，不是 affine；
- `U,V` 即 `quad_left,quad_right`，shape 都是 `[out_dim,q_b,state_dim]`；
- 五个确认实例配置均为 `q_b=4,kappa=0.05`；
- 没有额外 `W_o` tensor 或 bilinear bias；
- 三个分支先在每个 expert 内相加，再按 R03 的权重混合。

源码：`train_periodic_moe.py:1430-1495`。

关键 shape：

| 实例 | u input projection | p input projection | u `U/V` | p `U/V` |
|---|---|---|---|---|
| Circular H | `256×288` | `256×320` | `32×4×32` | `32×4×64` |
| Circular P | `224×256` | `224×288` | `32×4×32` | `32×4×64` |
| Square S | `224×229` | `224×233` | `5×4×5` | `4×4×9` |
| Square H | `256×267` | `256×278` | `11×4×11` | `11×4×22` |
| Square P | `224×252` | `224×278` | `28×4×28` | `26×4×54` |

### 7.3 初始化审计

类构造器本身将 `L` 和 nonlinear head 用小 gain Xavier 初始化，`U,V` 用 `N(0,0.015)` 初始化。但原训练流程随后执行 physical-zero residual initialization，把 expert linear、nonlinear final head、`U`、`V` 和 correction bias 都置零。由于二次项是两个因子的乘积，同时从零开始时两侧梯度也为零。

审计结论必须分三层：

1. **参数化允许二次响应**：是，formula 和 tensor 均存在；
2. **原版 Circular H/P 分支实际激活**：否，检查点中相关因子保持零；
3. **二次分支带来性能收益**：没有得到支持。修正版能激活分支，但 Circular P 平均精度未改善，Circular H 只有 `2/3` accepted，不能形成完整三种子改进结论。

修正版策略是保留一个因子的原生随机初始化、仅把另一个置零；初始二次输出仍为零，但零因子可获得梯度。修正版结果必须作为单独实验族报告，不能改写原版 checkpoint 的身份。

## 8. P01：压力门控、尺度和时间索引

### 8.1 adaptive gate 实例

Circular H/P 和 Square P 的 confidence head 为

```text
gamma = sigmoid(Linear(64,d_p)(GELU(Linear(h,64)(z))))
```

`gamma` 为逐 POD 压力分量向量，不是标量；最后一层权重在相应 H 变体中为零、bias 初始为 6（使初始 gate 接近 PPE base），具体初始化属于模型配置。该 head 与 encoder 共享 `z`，但不与压力专家共享参数。

正确组合是

```math
b_{n+1}=gamma_n \odot b_{n+1}^{PP}+rho^p_n,
```

而不是凸组合 `gamma*b_PP+(1-gamma)*b_D`。源码 `closure_components_torch` 的 `adaptive_gate` 分支明确令 `base_scale=alpha`、`residual_scale=1`（`train_periodic_moe.py:838-880`）。当前下载论文的式 (Appendix specialist details, lines 23-54) 已采用这一加性修正写法，较旧版凸组合表述正确。

网络输出先在标准化 target 空间中预测，再按 `pressure_next` scaler 反标准化，随后才与物理尺度 PPE candidate 组合（`train_periodic_moe.py:4055-4064, 4137-4177`）。两者在同一 chart 的压力 POD 坐标和 gauge 下组合。

时间顺序：先用 frozen `b_n/history/mu` 完成 velocity macro-step 得到 `a_(n+1)`，再用 `a_(n+1)` 计算 PPE base。默认 pressure path 的 learned correction/gate 来自当前 context 的编码；某些 `pressure_input_mode` 会用 `a_(n+1),b_PP` 构造 pressure state override 后再算压力专家，但 encoder/router context 仍来自当前 `a_n,b_n,history`。正文不宜把所有实例简化为“完全由更新后特征重新编码”。

### 8.2 实例例外

- Square S：`closure_mode=baseline`，实际是 `b_PP + residual`；存储的 confidence head 为 2 输出且在最终路径中跳过/冻结，不能称为 componentwise sigmoid gate。
- Square H：最终 overlap evaluator 的 `make_ops` 不用 PPE/gamma 组装；velocity 为直接 learned RHS，pressure 为直接 learned algebraic output。这是 data-only 推进例外。
- Square P：adaptive componentwise gate 生效。
- Circular S 与 Pinball S/H/P：不能用现有证据填入上述 sparse-MoE pressure 公式。

## 9. T01：一个时间步内到底重算什么

### 9.1 代码等价伪代码

```text
context C_n = {b_n, a_history, b_history, rhs_history, mu,
               chart scalers/operators, dataset clock/phase if configured}

function stage_rhs(a_trial, C_n):
    g_trial  = GalerkinRHS(a_trial, b_n, mu)
    xi_trial = Feat(a_trial, b_n, g_trial,
                    frozen histories, mu, phase)
    x        = standardize(xi_trial)
    z        = Enc(x)
    group    = group_route([z;x])       # learned/fixed/single
    top2_u   = channel_route_u([z;x], group)
    rho_u    = shared_plus_top2_u(z, current_a_slice(x), top2_u)
    return g_trial + rho_u              # residual-target instances

k1 = stage_rhs(a_n, C_n)
k2 = stage_rhs(a_n + dt*k1/2, C_n)
k3 = stage_rhs(a_n + dt*k2/2, C_n)
k4 = stage_rhs(a_n + dt*k3,   C_n)
a_next = a_n + dt*(k1 + 2*k2 + 2*k3 + k4)/6

b_PP = PressurePoissonCandidate(a_next, mu)
b_next = pressure_reconstruct(b_PP, current encoded context,
                              optional next-state pressure override)
shift histories with (a_next,b_next,new_rhs)
```

依据 `train_periodic_moe.py:4001-4069`，每次 `model_outputs_from_states_np(a_trial,...)` 都重新计算 `g`、base/history feature、标准化、model forward；`4072-4134` 的 k1-k4 每阶段均调用该函数。因此：

- 冻结：`b_n`、过去历史、参数和该步的外部 context；
- 重算：trial `a`、Galerkin RHS、当前 feature、`z`、组路由、u Top-2/weights、u expert outputs；
- 不用于 RK velocity 更新：压力通道路由/输出虽可能随完整 model forward 被计算，但 k2-k4 的 pressure result 被丢弃；最终 pressure 在 `a_next` 后重构；
- 当前 history shift 在 macro-step 完成后发生。

Circular H 的 stage-wise诊断中 Top-2 pair 未改变，但 gate L1 有微小变化；Circular P 中 stage 2/3/4 相对 stage 1 的 velocity pair change fraction 为 `0.72075`、group change fraction 为 `0.46140`。这直接否定“RK 内固定所有路由权重”的解释。

并非所有 specialist 都能写成相同 RK4：Square P 还有 8 个内部子步；Square H 是 data-only step 例外；Pinball B1 候选有自身更新结构。当前论文使用抽象 `Step_r` 并声明 nominal RK order 只针对 frozen-context velocity subproblem，是更稳妥的写法。

## 12. 建议用于第 3.2/3.3 的修订文本框架

### 12.1 第 3.2 节应新增的最小定义

建议主文只增加以下可理解、不会过拟合实现细节的内容：

> For a specialist equipped with internal sparse routing, the standardized history feature `xi` is encoded as `z=Enc(xi)`. The group and channel routers receive the concatenated routing feature `[z;xi]`. A learned group router applies a temperature-scaled softmax followed by a per-sample hard Top-1 selection, using a straight-through estimator during training; single-group and fixed-group instances bypass this learned choice. Within the selected group, independent velocity and pressure routers apply temperature-scaled softmax scores to six routed experts and retain the Top-2 after renormalization. The group-specific shared expert is excluded from this competition and remains active.

然后给统一权重式：

```math
\omega_0^c=\frac{\lambda_0}{\lambda_0+\lambda_r},\qquad
\omega_e^c=\frac{\lambda_r}{\lambda_0+\lambda_r}
\frac{p_e^c}{\sum_{j\in\mathcal T_2^c}p_j^c},
\quad e\in\mathcal T_2^c.
```

再注明 Circular H/P 用 `lambda_0=1,lambda_r=.75`，具体实例差异放附录。不要把这段写成九个 specialist 的普遍事实，除非先闭环 Circular S 和 Pinball 的模型身份。

专家公式可沿用当前逐输出公式，但正文增加一句：

> The nonlinear branch is an MLP applied to `[z;s^c]`; the explicit linear and rank-four quadratic branches act only on the current standardized channel state `s^u=a_tilde` or `s^p=[a_tilde;b_tilde]`.

压力部分建议写成带适用范围的形式：

> In adaptive-gate instances, `gamma=sigmoid(eta(z))` scales the algebraic PPE candidate componentwise and the learned pressure expert supplies an additive correction, `b_next=gamma⊙b_PP+rho_p`. Baseline and data-only exceptions are reported in the implementation table.

### 12.2 第 3.3 节应增加的时间推进说明

> During a velocity macro-step, pressure, past history and the physical parameter are frozen, but the current feature is not cached. Each Runge–Kutta stage substitutes its trial velocity into the Galerkin operator and reconstructs the current feature, encoder output, routing decisions, mixture weights and expert outputs. Pressure is reconstructed only after the velocity macro-step, after which the local history is shifted. The nominal Runge–Kutta order therefore applies only to the frozen-context velocity subproblem.

## 15. 核实判定

清单提出的四个核心实现问题已经对五个已确认 sparse-MoE 实例得到直接回答：

- `m*`：`[z;xi_std]` 经温度 softmax，逐样本 hard Top-1；训练用 ST；也存在单组/固定组。
- Top-2：u/p 独立 router，在已选组的 6 个 routed experts 内选择；shared 排除竞争且激活。
- `omega`：选中 routed softmax mass 先归一化，再按配置的 shared/routed 常量比例分配。
- `N`：对 `[z;s]` 做 projection + expanded residual FFN + output head；再与无偏置线性和逐输出 rank-4 二次分支相加。

但“覆盖全部九个论文实例”的完成标准尚未达到，原因不是公式未知，而是 Circular S 和 Pinball 的模型身份/架构与论文统一叙事不一致。此缺口应在论文中显式披露或通过进一步 identity audit 闭环，不能用通用 MoE 定义填补。
